# AtBots 0.3.0b1

This is an opt-in beta of the standalone `atbots` package and CLI, requiring
**Python 3.11 or later**. The native authentication dependency Pydantic AI 2.61
requires this floor; Python 3.10 users must remain on a compatible stable release.
Stable
`pip install atbots` users remain on the stable release.

```sh
python -m pip install --upgrade 'atbots==0.3.0b1'
atbots --new researcher --model qwen3:4b
atbots researcher
```

The chat example needs an already available local Ollama model. Installation does
not download a model, create credentials, enable remote inference or start a cloud
resource. Each named agent has a stable workspace, model binding, conversation
history and default AtMem memory scope. Pydantic AI owns its native model/tool
loop. Explicit CLI and conversational management share validated operations.

## Authentication and extras

```sh
python -m pip install --upgrade 'atbots[auth]==0.3.0b1'
atbots auth login chatgpt
# Optional platform clients/adapters:
python -m pip install --upgrade 'atbots[browser,schedule,supervision]==0.3.0b1'
python -m playwright install chromium
atbots ui
atbots runner --once
```

ChatGPT sign-in uses native Pydantic AI authentication; inference still requires
explicit plan-usage consent, remote configuration, eligibility and model access.
GitHub Copilot uses your own device-enabled OAuth application. Anthropic uses an
API key and the `anthropic` extra; Claude.ai subscription OAuth is unsupported.
No credentials are copied from other applications. Live subscription-provider
acceptance is not established by mocked authentication tests.

Named agents default to a new `~/.atbots/platform` store. Existing legacy
`~/.atbots/config.json` and the library API remain compatible. No automatic
migration of legacy conversations or memory is claimed. Explicit memory capture,
correction, forgetting and directional sharing use the backend's governance;
conversation logs are not automatically verified memory.

## Experimental platform scope

The beta contains durable job/approval records, workspace and browser tools,
reviewed skill loading, timezone-aware schedules, authenticated loopback web
management, AtSys supervision wiring and cloud-state/deployment adapters. They
remain experimental rather than a completed full-platform release.

- Browser execution requires Playwright/Chromium, approved domains/actions and
  a legitimate operator handoff for login, MFA or denied access. Directory scoping
  and browser permissions are not a security sandbox for arbitrary code.
- Schedules need an explicitly operated runner/service; installing does not make
  this computer continuously available. Pausing local work cannot undo external
  side effects. Interrupted uncertain effects require reconciliation.
- The `supervision` extra requires AtSys 0.3.0b4 or later. AtSys keeps independent
  worker/supervisor/repair policy, validator and reports. Mocked adapter checks do
  not prove real failure recovery across both products.
- AtFlows is optional observability, not a second execution owner. Native account
  transports are not silently redirected through a compatible proxy.
- Cloud deployment requires the `cloud` extra, an approved pinned image, explicit
  spending/state-transfer grants, credentials and external state. This release
  does not authorize provisioning resources or prove a live cloud deployment.
  Desktop keychains and browser sessions are not exported as portable state.

Known-pattern secret screening is not comprehensive DLP. Native model usage is
not a hard billing cap; unknown dollar cost remains unknown. A chat response or
successful process exit does not establish that an arbitrary objective succeeded.
Feature 006's remaining acceptance and migration work stays open.

## Verification

Release checks and their exact results are recorded in
`specs/007-beta-release/verification.md`. Deterministic tests use temporary local
stores, fake authentication and native Pydantic AI test models. Opt-in paid/live
model evaluations are excluded from the default suite. Short browser/package
checks are not overnight, cross-provider or production cloud qualification.

# AtBots 0.3.0b2 — UI-first agents with private memory and supervision

Python 3.11+ is required. This is an opt-in beta of the standalone `atbots`
package, not AtMem's separate legacy companion distribution.

```sh
python -m pip install --upgrade 'atbots==0.3.0b2'
atbots --version
atbots
```

## Your first agent

1. Open **Setup & connections**. Connect ChatGPT/Codex or GitHub Copilot through
   supported account sign-in, or add an OpenAI/Anthropic API key to the OS keychain.
2. Choose **Control room model**. Select a connection and available model; review
   remote-inference permission. Setup works even if the previous model is offline.
3. Click **New agent**, choose a name/model and file permissions, then approve.
4. Select it. **Environment**, **Memory** and **Files** show its own workspace,
   AtMem and capabilities. Other agents cannot recall its memory. Provider
   connections are reusable; private memories and conversations are not shared.
5. For supervised work, open **Supervision**, start its private AtSys, and save
   worker/supervisor CLI, model and acceptance-command settings. Fresh Codex
   workspaces offer explicit local Git initialization. The coding CLI must be
   installed and signed in. Ask the agent to use AtSys and approve its proposal.

See the [step-by-step guide](../agent-platform.md). The default command starts
one private local UI/background schedule runner. Closing the tab or launching
terminal does not stop it; the PC must remain awake. Idle agents make no model
calls. OS boot auto-start is not installed.

## Changes from 0.3.0b1

- Guided reusable provider setup, model catalogs and direct control-room switching.
- Strict per-agent memory walls, callable memory tools and truthful environment
  identity; legacy sharing edges no longer authorize recall. Data is retained.
- Private workspaces, conversation restoration and separate per-agent drafts.
- Native, approval-bound memory/schedule/supervision proposals and readable receipts.
- Private AtSys startup, health checks before approval consumption, durable
  task reports and verified idle shutdown without restarting shared services.
- Component version visibility and confirmed compatible upgrades, with pause/
  quiescence checks, private-service shutdown and required app restart.
- Lazy browser MCP startup: discovering tools no longer launches Chrome.

Existing agents, credentials and legacy `~/.atbots/config.json` are retained.
Named agents use `~/.atbots/platform`; no automatic legacy-memory migration or
permanent agent deletion is performed. Archive/pause remain explicit operations.
No provider/model or file grant is silently changed on an existing agent.

## Optional capabilities and compatibility

Base installation includes authentication, scheduling and AtSys package support.
Browser work also needs:

```sh
python -m pip install --upgrade 'atbots[browser]==0.3.0b2'
python -m playwright install chromium
```

AtMem >=2.3.10,<3 and AtSys >=0.3.0b4,<0.4 are required dependencies. AtFlows
is optional observability and needs its configured service; native account
transports are not silently redirected through a proxy. Installed packages are
shared by the app environment, while agent memory/state/configuration are private.
Windows UI support does not imply Windows native AtSys workspace execution;
that supervision path currently requires macOS/Linux.

Copilot first sign-in needs your own device-enabled OAuth app Client ID.
Provider eligibility/model entitlement is checked separately from login.
Anthropic API keys are supported; Claude.ai subscription OAuth is not fabricated.
Installing does not call a paid model, download an Ollama model, copy other
applications' tokens or provision cloud resources.

## Verification and boundaries

The development candidate passed 253 source tests and 181 installed tests on
macOS, real desktop/mobile browser checks, real Copilot memory/environment/file
tools and a Copilot-proposed, Codex-executed, independently validated AtSys task.
Release-specific checks are recorded in
[release verification](../../specs/007-beta-release/verification-0.3.0b2.md),
with earlier failures retained in
[corrective evidence](../../specs/006-agent-control-room/corrective-verification-20261027.md).

This corrective beta is not full platform acceptance. Legacy companion/custom
loop migration, broader live-provider/vision qualification and cloud acceptance
remain open. A model response is not independently verified task success;
uncertain external effects are not blindly replayed. Workspace scoping is not
an OS sandbox for trusted executable coding CLIs. Component upgrades require
operator confirmation and compatible versions; no automatic rollback is promised.
No cloud deployment or website publication is part of this release.
